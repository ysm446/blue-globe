## ニュース文の作り方

朝に見るアプリなので、普段は今日の話をする。18時からは明日の話に切り替える。

1. 見出し、現在の天気、その日の天気と最高・最低気温、降水確率は、テンプレートで作る。
   - 今日の値は、過去の時間帯を含めず、今の時刻から今日の終わりまでの時間別予報から求める(週間予報の「今日」も同じ)。
2. 見通しは、気象庁の文からその日の分を取り出す。夕方の発表などで今日の分がなければ、明日の分を使う。
   - 1文なら LLM を通さず、文末を「見込みです」に揃える。
   - 「〜見込みです。このため、〜」は「〜ため、〜」とルールでつなぐ。
   - それでも複数の文が残るときだけ LLM で1文にまとめる。
3. LLM の出力は検査し、落ちたら気象庁の原文を表示する。
   - 原文にない語の追加、雷や時間帯などの欠落、地域名の欠落、書き出しと文末、長さを見る。
4. 気象庁の文がない地点(海外、奄美地方)は、見通しの文を出さない。その日の文と週間予報で伝わるため。

ルールを優先するのは、`gemma-4-E4B` に全文を任せると「晴れ」が「晴」に崩れるなどの誤りが出たため。

Open-Meteo の予報値と気象庁の文は別の予報なので、食い違うことがある(2026-11-01 の東京: 予報値は「晴れ時々曇り」、気象庁は「曇り」)。出典は画面に明記している。

## 地図の表示モード

左上のボタンで切り替え、選んだモードは保存する。データはそのモードに入ったときに初めて取得する。

| モード | 地球儀に描くもの | データ |
|---|---|---|
| 通常(既定) | 写実的な地球、昼夜、街明かり、大気、実際の星、太陽、月。雲は描かない | 同梱の画像と星データ |
| 天気 | 通常に加えて雲 | NOAA GMGSI(衛星の赤外合成、約8km、毎時)と GFS 全層雲量 |
| 風速 | 風の粒子と風速の色。昼夜も天体も描かない | GFS 地上風(1度格子) |

通常モードは、回して触れる地球儀であることを優先する。風の粒子は風速モードのときだけ動かす。

カメラの距離は、通常・天気モードが地球全体の見える 3.3、風速モードが粒子の見やすい 2.15。モードを切り替えると、向きは保ったまま距離だけ変える。

## 写実的な地球と天体

- 地表と夜の街明かりは 8192×4096 の JPEG を `assets/textures/` に同梱する(NASA Blue Marble / Black Marble、GIBS から取得)。file:// の画像は WebGL で使えないので、メインプロセスからバイト列で受け取って読み込む。
- 昼夜はシェーダーで描く(`src/renderer/earth.ts`)。夜側も回したときに場所が分かるよう、完全な黒にはしない。
- 太陽、月、恒星の方向は日時から計算し(`astro.ts`、`sky.ts`)、1分ごとに更新する。太陽と月は普段は画面外にあり、地球を回すと見える。大きさは誇張しており、月は実際の約3倍。月の模様はノイズで作った見た目だけのもの。
- 星は Hipparcos 由来の6等星までの 5,026 個(`src/renderer/data/stars.json`。d3-celestial の `stars.6.json` を変換。0.2° 未満に重なる 5 等より明るい星は、光が足されて四角くにじむので 1 つにまとめた)。J2000 座標のままで、歳差の分(2026年で約0.36°)は補正していない。
- GIBS の案内に従い、謝辞を設定画面と README に載せる。

## HDR 的な描画と露出

モニターの HDR 出力ではなく、SDR の画面で見るための計算(`src/renderer/hdr.ts`)。2026-11-01 時点の環境は SDR 接続(`dynamic-range: high` が false)で、Electron 33 の WebGL には HDR 出力の正式な手段もない。

- 通常・天気モードは、明るさの上限がない 16 ビット浮動小数点のバッファへ描き、明るい部分をにじませ(ブルーム)、最後に ACES で画面の明るさへ変換する。風速モードは元の見た目を保つため、この処理を通さない。
- にじむのは太陽の中心、街明かり、海の映り込み、明るい星など、値が 2.6 を超える部分だけ。陸、雲、氷はにじませない。
- 露出は太陽と地球の位置関係から決める(`exposure.ts`)。太陽が見えると最大 0.3 倍まで絞り、夜側を見ているときは 1.25 倍に開ける。絞るのは 0.35 秒、開けるのは 1.4 秒の時定数で、目が慣れる動きに近づけている。画面の明るさの実測はしない。
- 星は相対的な明るさの差を等級どおりに出す(5 等級差で 100 倍、`starIntensity`)。絶対的な明るさは実物に合わせず、設定のスライダーで全体を上げ下げする(×0.125〜×8。星同士の比は変わらない)。
- 星は中心を鋭く描き、明るい星は飽和した範囲の大きさと、計算で描く丸い光で差を出す。値はブルームのしきい値より低く抑える。ブルームに通すと明るい点が四角くにじむため。
- 太陽は画像ではなく計算で描く。8 ビットの画像を明るくすると、暗い部分に同心円と点の模様が出たため。明るい部分が広いとブルームで四角くにじむので、中心だけを小さく明るくしている。

## 描画の設定

設定画面の「描画」から変えられ、すぐ反映して保存する。FPS 上限(モニターに合わせる / 120 / 60 / 30)、描画解像度(100 / 75 / 50%)、星の明るさ、光のにじみ、自動露出、海岸線と国境線(通常・天気モードのみ。風速モードでは常に描く)、FPS の表示。既定は従来と同じ見た目と動作。

風の粒子は 1 回の更新で動く量が一定なので、更新回数を毎秒 120 回に固定し、描画の FPS とは切り離す。FPS を下げても風の速さと軌跡の長さは変わらない。その分、風速モードでは粒子の計算量が減らない。カメラの慣性も、FPS によらず同じ時間で止まるように換算する。

## 天気モードの雲

雲の質を決めるのは描き方より元データなので、衛星の実データを主に使う(`server/clouds.py`)。7.4MB の NetCDF を取得し、4096×2048 の雲マップに変換して `data/cloud-cache/` に置く。取得できなければ前回のマップ、それもなければ GFS だけで表示する。

- **薄い雲も濃い雲も衛星から作る:** 以前は薄い層を GFS から足していたが、格子が粗く、濃い雲と形がつながらなかった(インド洋で見えていた雲の 63% が GFS だけの雲だった)。濃さは赤外の値から連続的に求める。
- **GFS は補助に使う:** 晴れた場所の値は緯度で大きく違う(熱帯で約 73、南緯 60 度で約 136)ので、GFS が晴れとする場所から緯度ごとの基準を求める。冷たい地面は雲に見えるので、GFS が晴れとする場所では抑える。衛星のない極付近(約 ±72.7° より外)は GFS で埋める。
- **低い雲は少なく見える:** 赤外では暖かい低い雲が写りにくい。別のデータで補うと形がつながらないので、補っていない。
- **描き方はボリューム雲を使わない 2.5D:** 地表より少し高い別の球に載せ、回すと地面とずれて動くようにする。透明度は厚みから指数的に計算し、薄い雲は地面が透け、縁では濃くなる。太陽の方向へ 4 点たどって遮られた分を青灰色に暗くし、太陽が低いほど長い影を地面に落とす。
- **細部のノイズは見た目だけ:** 薄い雲の縁はノイズで少し崩しており、その部分は観測された形ではない。
- **地図の版:** 作り方を変えたら `MAP_VERSION` を増やす。同じ時刻のデータでも古いキャッシュを作り直す。
- **NOAA の条件:** 加工したデータを元データのように示さない。凡例と設定画面に「加工」と明記する。
